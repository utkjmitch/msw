# What in MSW got in the way: PickProphets live walk, 2026-10-15

A list for plan B, ordered by how much each item cost this run. Each item says what happened and what would fix it.

There was no `origin/mfx/msw-cc-walk-1` branch to learn from: `git fetch` at the start listed `dev`, `main`, `mfx/msw-plan-a-fixes`, `mfx/msw-walk-server` and `mfx/rules-cleanup` only.

1. **Read-only mode blocks reads that travel as POST.** PickProphets loads its data from Firestore. Firestore reads go over a `POST .../Firestore/Listen/channel` request. The server blocked 73 of them as `background-write`, plus 56 `Write/channel` and 12 `usagePing` posts. The site never got its data, so the leaderboard said "0 Total Participants", the weekly slate said "No NFL games scheduled yet", and the week arrows and "Sign in to join" did nothing. None of those can be reported as site defects. Adding `https://firestore.googleapis.com` to `origins` would not help: in read-only mode every POST to a journey origin is blocked as `would-submit`. Fix: a journey field for read channels (method + URL pattern) that read-only walks let through, recorded in the manifest, and a run-health warning when a walk blocks a large number of background posts to one endpoint.
2. **Single-page sites fail the Dead Parrot check every time.** All 9 walks (8 Survey, 1 Inspection) ended `verified: true, alive: false`. Every failure was "page X has 1 screenshot" (twice also "no instrument record"). The page text changes between the two arrival looks taken one second apart (spinner, then content), so they hash to two states with one screenshot each. Fix: take the second look after the page settles, or hash the settled state only, or count a state that replaced the first within the arrival window as the same arrival.
3. **"The page changed; look again" on pages that keep updating.** Three acts were refused because the state moved between the look and the act (a timestamp, a late-loading list). Refusals are free, but each costs a round trip. Fix: the same settle rule as item 2, or ignore text that differs only in a clock value.
4. **No way to use a newly registered MCP server in the session that registered it.** `claude mcp add` worked and `claude mcp list` showed `✔ Connected`, but the running session cannot see new tools. I drove the server through a small MCP client bridge (`tools/bridge.mjs` + `tools/c`, an HTTP shim on 127.0.0.1:4999). Fix: document a supported route: register before the session starts, or ship an `msw walk` client that a running agent can call.
5. **`out_dir` resolves from the server's start directory, not from the run file.** Registered with `claude mcp add`, the server starts in the repo root, so `out_dir: "."` would have written walks into the repo root. The bridge sets the working directory to the run folder. Fix: resolve `out_dir` (and Walker and journey paths) relative to the run file.
6. **The Inspection has no tooling.** Plan A has no `msw-guide` or `msw-inspect` skill and no `guide.md` writer. I wrote `guide.md` by hand and ran the Inspector as a separate `claude -p --model sonnet` session limited to the five msw tools. Two gaps showed: the server makes the Inspector start as a Walker (it needs a dossier and journey, then rates options and answers the Wharton questions as that person), and "web blocked" is only a tool allow-list, not a network rule. Fix: an `inspect` mode in `start_walk` that takes a guide, plus the two skills.
7. **The personal-data mask eats numbers.** Score ranges such as "113.0 - 117.7" and chart axis labels ("-50 -40 -30 ...") came back as `[masked]` in look text, and ISO dates in console logs are masked as phone numbers. The Walker lost real content. Fix: tighten the phone pattern (require a phone-like grouping, skip decimals and ISO dates).
8. **Options are offered for links the Walker cannot press.** On the phone, the footer "Leaderboard" link was listed while the cookie box covered it. The act failed with `elementHandle.tap: Timeout 5000ms exceeded` and still cost patience. Fix: drop or mark options whose centre point is covered by another element, and treat a failed tap as a refusal, not a patience charge.
9. **Web vitals carry over between client-side routes.** LCP is identical across `/`, `/predict` and `/leaderboard` in one walk (8,248 ms on slow 3G), so "Slow or unstable page" is repeated per route with the first load's numbers. Fix: reset or label vitals on soft navigation.
10. **axe records give counts, not elements.** "Buttons must have discernible text, nodes: 4" does not say which buttons. The report had to match them to what the Walker saw. Fix: keep the first few node targets and their HTML snippet (masked) in the instrument record.
11. **The run-away floor raises cosmetic findings.** When a walk ends in a run-away, every Walker finding at the final step is raised to 3. A severity-1 note about a font, and a severity-2 note about icon labels, became 3. This is the open decision in the plan A fixes report; this run is one more data point against applying it to every finding on that step.
12. **Option numbers shift between pages, and a stale number acts on the wrong control.** On one walk I sent option 8 ("scroll down" on the previous page) after navigating; on the new page 8 was a link back to Learn, and the walk lost two patience. The rule "act must follow a look of the same page state" passed because I had looked. Fix: let `act` take the option's label as well as its number and refuse when they disagree.
13. **The server needs Node 22; the box has Node 20.** `npm ci` warned `EBADENGINE`, but build, typecheck and all 82 tests passed on Node 20.20.2.
14. **The example run file does not validate against `formats/run.schema.json`.** `examples/run.json` omits `test_copy`, `seeded_data`, `allowed_for_transact`, `payment_test_mode` and `mask_personal_data`, which the JSON Schema marks required (the zod loader fills defaults). Fix: make the JSON Schema match the loader, or fill the example.
